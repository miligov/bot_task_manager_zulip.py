# Исправлено обрезание имени вложения при переносе из Zulip в Redmine

## Проблема
При создании задачи или добавлении комментария через бота имя прикреплённого файла
попадало в Redmine в обрезанном/искажённом виде (терялась часть названия, русские
буквы приходили в виде `%D0%9E%D1%82...`, файлы с одинаковыми именами перетирали друг друга).

## Причина
1. В `sanitize_filename()` имя перекодировалось в `windows-1251` с параметром
   `errors="ignore"` — все символы, отсутствующие в этой кодировке (эмодзи, спецсимволы,
   отдельные типографские знаки), молча удалялись из имени.
2. Имя файла бралось только из последнего сегмента ссылки `/user_uploads/...`,
   который у Zulip URL-кодирован и не совпадает с реальным названием файла.
3. Регулярное выражение поиска вложений некорректно обрабатывало markdown-ссылки
   вида `[Имя файла.docx](/user_uploads/...)` — символ `]` попадал внутрь пути.

## Что сделано
Файл: `bot_task_manager_zulip_quote.py`, блок «РАБОТА С ВЛОЖЕНИЯМИ ИЗ ZULIP».

- `sanitize_filename()`: символы, непредставимые в windows-1251, теперь **заменяются
  на `_`, а не удаляются**; добавлено снятие URL-кодирования (`unquote`), замена
  запрещённых в ФС символов, защита от path traversal.
- Усечение имени выполняется только при превышении лимита файловой системы
  (200 байт) и **с сохранением расширения файла**.
- Добавлен `UPLOAD_MD_RE` — отдельный разбор markdown-ссылок; отображаемое имя из
  ссылки используется как приоритетный источник названия файла.
- Добавлен `_filename_from_response()` — резервное получение имени из заголовка
  `Content-Disposition` (поддержка `filename*=UTF-8''...`).
- Добавлен `_unique_path()` — файлы с одинаковыми именами больше не перетираются
  (`file.png`, `file_1.png`, ...).
- В `collect_uploads_from_content()` добавлена дедупликация по пути вложения:
  один и тот же файл не скачивается и не прикрепляется дважды.
- Добавлено логирование факта скачивания вложения (исходное имя → путь сохранения).

## Приоритет определения имени файла
1. Имя из markdown-ссылки `[Имя](/user_uploads/...)`
2. Заголовок `Content-Disposition` ответа Zulip
3. Последний сегмент URL (с декодированием)

## Результат
Имя вложения в Redmine полностью совпадает с именем файла в Zulip, включая пробелы,
кириллицу, скобки и номера. Дубликаты вложений не создаются.

## Как проверить
1. Отправить боту сообщение с упоминанием и вложением, имя которого содержит
   пробелы, кириллицу и скобки (например `Отчёт по задаче №5 (финал).docx`).
2. Открыть созданную задачу в Redmine — имя вложения должно совпадать полностью.
3. Повторить для режима комментария (`+ #id`) и для нескольких вложений в одном сообщении.
